# Zytadelle

An idle cell-defense game. Play a culture (a run) that plays out in 35-second cycles until the
cell dies. Built with .NET MAUI Blazor Hybrid, Windows-only for now.

## Gameplay

Each run is a single culture defending itself for 35 seconds. When the cell dies, the DNA it
earned banks into permanent levels in the **Gene Lab** — the progression layer that carries over
between runs and makes each successive culture stronger. There's a separate **Balance Lab** tool
(see below) used to tune the game's numbers; it isn't part of the game loop itself.

## Prerequisites

- .NET 10 SDK
- Windows (WebView2 Runtime — usually already present on current Windows 10/11)

## Running it

```
dotnet run --project src/Zytadelle.App    # the game
dotnet run --project src/Zytadelle.Lab    # Balance Lab
dotnet build                              # build everything
```

## Architecture

Five projects, in dependency order:

| Project | Purpose |
|---|---|
| `Zytadelle.Balancing` | Every tuning number in the game (constants, curves, modifiers) — the only source of numbers with balancing meaning. No logic beyond curve math. |
| `Zytadelle.Core` | The game engine: simulation, persistence, missions, upgrades. Deliberately has no balancing knowledge of its own — it reads everything from `Zytadelle.Balancing`. |
| `Zytadelle.Lab.Engine` | Plain C#, no UI. Tuning-set diffing and balance search (Cross-Entropy priority search or an exhaustive grid) over `Zytadelle.Balancing`. |
| `Zytadelle.Lab` | MAUI Blazor Hybrid UI over `Zytadelle.Lab.Engine`. Every balancing number is a form field, generated by reflection rather than hand-maintained. |
| `Zytadelle.App` | The game itself, MAUI Blazor Hybrid. |

Rendering in `Zytadelle.App` is split across a boundary: C# encodes world state as bytes
(`FrameEncoder`), and JavaScript in `wwwroot/js/` decodes and draws it to canvas (`arena.js`).
The byte layout is mirrored by hand on both sides, so a change to one always needs a matching
change to the other.

`Zytadelle.Balancing` is the single source of truth for every gameplay number — nothing balancing-
related lives in `Core` or `App`. Its XML doc comments aren't just documentation: the Balance Lab
reads them at runtime as input hints for the generated form fields.

## The Balance Lab

A tool for balancing: every number from `Zytadelle.Balancing` is a field in its form (generated by
reflection, no manually maintained list). It simulates campaigns under different Gene Lab / in-run
priorities — either a priority search (Cross-Entropy method) or an exhaustive grid over a chosen
gene subset — and returns the five best builds. For each build, a ladder table shows how many runs
and how much time (simulated, and in real time at a chosen speed) were needed to reach each next
best cycle. Changed values can be exported as a diff plus a C# snippet, to be applied manually back
into `Zytadelle.Balancing`.
